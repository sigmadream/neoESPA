# 백엔드 테스트 코드 개선 및 TDD 고도화 로드맵

본 문서는 neoESPA 백엔드 시스템의 안정성과 신뢰성을 확보하기 위한 테스트 코드 개선 사항을 기술합니다. 향후 테스트 주도 개발(TDD)을 고도화하는 과정에서 우선순위에 따라 단계별로 적용할 것을 권장합니다.

## 1. 테스트 커버리지 측정 및 시각화 (Code Coverage)
현재 구현된 테스트가 소스 코드의 로직을 어느 정도 검증하는지 정량적으로 파악하기 위한 도구를 도입합니다.
- 제안 도구: pytest-cov
- 목표: 핵심 비즈니스 로직(Services, Domains)에 대해 90% 이상의 구문(Statement) 및 분기(Branch) 커버리지를 유지합니다.
- 기대 효과: 미검증 경로를 통한 잠재적 결함을 최소화하고 전체적인 코드 품질을 수치화할 수 있습니다.

## 2. 데이터 팩토리 도입 (Data Factories)
복잡한 모델 관계를 가진 테스트 데이터를 선언적으로 생성하여 테스트 설정의 복잡도를 낮춥니다.
- 제안 도구: factory_boy
- 목표: 과제-제출-결과-피드백으로 이어지는 객체 그래프 생성을 자동화합니다.
- 기대 효과: 테스트 코드의 가독성이 향상되며 데이터 설정에 소요되는 시간 복잡도를 개선할 수 있습니다.

## 3. 속성 기반 테스트 도입 (Property-Based Testing)
고정된 테스트 케이스의 한계를 극복하기 위해 임의의 데이터를 활용한 검증을 수행합니다.
- 제안 도구: Hypothesis
- 목표: ZIP 파서의 입력 구조나 점수 계산 로직에 대해 임의의 입력 조합을 생성하여 시스템의 불변성(Invariants)을 검증합니다.
- 기대 효과: 개발자가 인지하지 못한 경계값 오류나 에지 케이스(Edge case)를 효율적으로 식별할 수 있습니다.

## 4. 서비스 레이어의 격리 및 모킹 강화 (Mocking & Isolation)
외부 의존성과의 결합도를 낮추어 단위 테스트의 독립성과 실행 속도를 확보합니다.
- 제안 도구: unittest.mock
- 목표: 파일 시스템 I/O, 외부 API 호출, 관측성 서비스(observability_service) 등을 철저히 격리합니다.
- 기대 효과: 특정 모듈의 수정이 타 모듈 테스트 실패로 이어지는 연쇄 효과를 방지하고 테스트 실행 시간을 단축합니다.

## 5. 환경 일치성 검증 (Environment Parity)
테스트 환경과 운영 환경의 불일치로 인한 잠재적 오류를 예방합니다.
- 제안 도구: Testcontainers (PostgreSQL 등 실제 DBMS 컨테이너 활용)
- 목표: SQLite와 실제 운영 DBMS 간의 특성 차이로 발생할 수 있는 쿼리 오류나 제약 조건 위반을 포착합니다.
- 기대 효과: 운영 환경 배포 시점에 발생할 수 있는 데이터베이스 관련 결함을 사전에 차단합니다.

## 6. 비동기 테스트 최적화 (Async Testing)
FastAPI의 비동기 특성을 고려하여 실제 실행 환경과 유사한 검증을 수행합니다.
- 제안 도구: httpx.AsyncClient, pytest-asyncio
- 목표: 비동기 엔드포인트의 병행 처리 능력과 자원 경합(Resource Contention) 문제를 검증합니다.
- 기대 효과: 고부하 상황에서의 시스템 처리량(Throughput) 저하나 데드락 가능성을 사전에 파악할 수 있습니다.
